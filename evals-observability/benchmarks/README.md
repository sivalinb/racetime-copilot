# Benchmarks and interpretation

## Evidence selection — rerunnable

[evidence-latest.json](evidence-latest.json) is generated by `npm run eval:benchmark`. The candidate passes a case only when its sorted selected evidence IDs exactly match the golden IDs. The baseline selects any temporal overlap and ignores availability, full containment and suspicious source instructions. It is intentionally simple, not a competing LLM.

| Metric | Meaning |
|---|---|
| `passed / count` | Exact-match candidate cases; currently 40/40 |
| `baselinePassed / count` | Same cases and expectations; currently 20/40 |
| `groups` | Results by boundary, scenario, availability and source-instruction group |
| `p50Ms`, `p95Ms` | Nearest-rank percentiles over 40 local in-process case runs |
| `cases` | Expected, actual and baseline IDs, pass flags, duration and trace for every case |
| `datasetSha256`, `codeHashes` | Exact dataset and relevant source bytes used |
| `sourceCommit`, `workingTreeDirty` | Checkout provenance when run; dirty runs are explicitly identified |
| `runtime` | Node version, OS and architecture; useful when comparing timings |

The command fails on a dataset checksum mismatch, invalid/duplicate IDs, any failed golden case, or a failed conflict/retry/cache demonstration. It does not fail on a latency threshold: there is no measured production SLO yet. No model/provider calls occur; `providerCostUSD: 0` excludes compute and development costs. These timings cannot be compared directly with Gemini video-job timings.

`evidence-latest.json` is replaced by each run. Preserve a dated copy before comparing revisions. Running the benchmark changes result files but never the frozen dataset. A dirty flag is expected when developing or refreshing results; the recorded code hashes identify the evaluated files.

## Routing specialization — recorded experiment

[router-recorded.json](router-recorded.json) is a snapshot of the existing LoRA experiment, not a new training run performed by the benchmark command. Both arms train the classification head; the LoRA arm also trains rank-8 query/value adapters.

| Metric | Frozen encoder + trained head | LoRA encoder + trained head |
|---|---:|---:|
| Held-out accuracy | 52.5% | 70.0% |
| Macro F1 | 0.522 | 0.709 |
| Trainable parameters | 516 | 8,708 |

The report includes class precision/recall/F1, confusion matrices and 40 predictions per arm. [router-merge-recorded.json](router-merge-recorded.json) records adapter/merged-model logit agreement within `1e-5`. This is an encoder classification experiment, not a video model, and the adapter is not used by the live planner. Reproduce separately using [training/README.md](../../training/README.md); training downloads model weights and has its own dependencies.

## Other verification

The existing [TypeScript tests](../../tests/core.test.ts) and [21 Python product tests](../../tests/product_test.py) check implementation contracts such as time boundaries, account isolation, durable review, retry/cancellation, leases and usage limits. They are tests, not additional benchmark samples. Run them with `npm test` and `python -m unittest discover -s tests -p product_test.py`.

The [video integration snapshot](../observability/examples/video-integration-recorded.json) confirms a real provider round trip on a six-second synthetic clip and review after restart. Real race accuracy, active live capture and external LangSmith ingestion remain separate validation work.
